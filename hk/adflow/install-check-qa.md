# 安裝代碼失敗 QA

安裝檢查未收到該廣告位的匹配請求？請按以下順序排查。此檢查只查詢真實請求，不會發起測試流量。

::: tip 甚麼算安裝檢查通過？
目標網站上的廣告位發出的真實 Bid Request 到達 Prebid Server，即視為安裝檢查通過。沒有廣告返回、`NO_BID`、競價篩選或暫未展示，是後續競價與展示問題，不等於代碼沒有安裝成功。
:::

## 1. 確認代碼已發佈，並開啟目標頁面 {#publish}

只點擊網站後台的「儲存」或「發佈」，不會保證已經開啟的網頁自動重新載入。請開啟或重新載入已發佈的、安裝該廣告位的正式頁面。如果網站有快取或 CDN，請確認它已提供最新頁面代碼。預覽頁、測試環境與正式頁可能不同。

## 2. 核對兩段代碼與廣告位 {#codes}

### 共用腳本和廣告位代碼都在目標頁面嗎？

請對照 AdFlow 的兩步安裝代碼。共用腳本應正確載入，目標廣告位代碼亦須在同一頁面；不要只安裝其中一段，亦不要放錯頁面範本。同一網站範本的共用腳本只安裝一次。

確認代碼取自 AdFlow 中對應網站和廣告位的正式代碼，而非範例。兩步安裝方式見[接入指南](./integration-guide#adflow-usage)。

### 帳號與廣告位 ID 是否匹配？

確認 `data-account-id` 和 `data-placement-id` 與本次檢查的帳號、廣告位一致，且該廣告位屬於目前選擇的網站。多個帳號或廣告位的代碼不要混用。不確定時，請從 AdFlow 對應廣告位重新複製代碼。

## 3. 觸發一次真實廣告請求 {#trigger}

重新載入頁面後，確認廣告位所在區域實際載入。若網站使用延遲載入、單頁路由或需要互動才能觸發廣告位，請捲動至廣告位或完成對應操作。在瀏覽器的 **Network** 面板確認有請求，再回 AdFlow 重新執行安裝檢查。

## 4. 查看瀏覽器攔截與錯誤 {#browser}

可請網站開發者開啟瀏覽器開發者工具的 **Network** 與 **Console**，依次檢查：

- AdFlow 腳本是否已載入並執行？
- 是否有 JavaScript 錯誤？
- 內容安全策略（CSP）是否攔截腳本或請求？
- 是否有網絡請求失敗，或瀏覽器擴充功能攔截？

請開發者修復網站或網絡設定問題。診斷時可在自己的測試瀏覽器暫時排除擴充功能的攔截影響，不應要求所有訪客關閉安全設定。

可參考[接入指南中的診斷工具](./integration-guide#adflow-diagnostic)。收到請求後仍有競價或展示問題時，請使用對應的[廣告格式調試器](./integration-guide#adflow-sdk)或 [S2S 調試器](./s2s-debugger)。

## 5. 稍後重試，確認檢查對象 {#retry}

請求記錄可能有短暫處理延遲。請稍後再試，並確認 AdFlow 目前選擇的網站、廣告位與剛才實際瀏覽的頁面一致。

新建廣告位的外部 ID 可能尚未同步到檢查所用的資料，建議建立後等待 1-2 分鐘再觸發檢查；從請求發出到檢查可查通常亦存在分鐘級延遲，剛觸發的請求可能需要稍等才會出現。

若頁面已正確安裝但檢查仍失敗，請在瀏覽器的 **Network** 面板確認是否有發往 Prebid Server 的請求，以及該請求是否攜帶了正確的 publisher ID 與 placement ID。

目前未查到匹配請求不代表完整歷史中從未出現請求，亦不能直接判定唯一原因。如果是檢查操作本身失敗，請稍後重新檢查，不要據此認定代碼安裝失敗。

::: tip 檢查結果顯示「未知」（unknown）時
當報表通道暫時不可用，檢查會回傳「未知」而非「未查到」。這不是安裝問題，而是系統暫時無法核查，請稍後再試；若持續出現，請按下方聯絡方式提交客服。
:::

## 6. 確認帳號、網站與廣告位狀態 {#states}

安裝檢查只會查詢狀態正常對象上的真實請求，以下狀態會導致本次檢查查不到匹配請求：

- **廣告位狀態不是 `active`。** 新建廣告位預設為 `pending`（待驗證），需代碼安裝成功並觸發驗證後才會變為 `active`；若為 `disabled`（已停用），請在 AdFlow 後台啟用或聯絡管理員。
- **網站狀態不是 `active`。** 檢查要求對應網站（Website）處於 `active` 且未被刪除；若網站被停用，該網站下所有廣告位的檢查都會失敗。請在 AdFlow 網站管理中確認網站已啟用。
- **帳號已被停用。** 帳號被停用後，所有廣告位的檢查請求都不會被查詢。請確認 AdFlow 帳號處於 `active`；若顯示已停用，聯絡管理員恢復。

## 仍然無法解決？ {#help}

請透過 AdFlow 右下角的現有客服聯絡人工支援，並提供：

- 網站網域、實際頁面 URL。
- 廣告位 ID。
- 代碼發佈時間、最近檢查時間及對應時區。
- 相關 Network / Console 截圖。
- 廣告位與網站的目前狀態（`pending` / `active` / `disabled`）。
- 檢查結果類型（收到真實 Bid Request / 未查到 / 未知）。
- 頁面代碼中的 `data-account-id`、`data-placement-id` 值，以及是否與 AdFlow 後台顯示一致。

請勿提供帳號密碼、金鑰或訪客私隱資料。
